## 1. 阶段总览

PROJECT.md 的“八阶段”本质上是八项功能里程碑。直接按八个小阶段逐个完成，会导致每个阶段都无法独立交付。因此保留其顺序与覆盖范围，合并为五个可验收的交付阶段。

| 阶段 | 范围（对应原里程碑） | 交付物 | 验收标准 |
|---|---|---|---|
| P0（已完成） | DeepSeek API 接入、环境、Git | 连通性脚本、仓库 | 已达成 |
| **P1**：工程骨架 + Excel 读取与结构探查 | 原“Excel 读取”；铺垫原“Excel 数据分析” | 可运行的 `inspect` 命令，对任意源文件输出结构报告 | 给定混乱样例，能正确报告 Sheet、候选表头、数据行列范围、基础质量问题；全流程不依赖 AI、可离线测试 |
| P2：分析深化 + 映射方案与 AI 工程化 | 原“数据分析 + 字段映射转换”+ AI 模块正式化 | 结构分析报告、可复用映射方案（YAML）、AI 映射建议与确认流程、首条真实链路转换 | 一张真实来源文件可经“映射方案 + 清洗”转换为标准字段，AI 仅提供候选且全程留痕 |
| P3：清洗与编码规则引擎 | 原“数据清洗 + 编码规则” | 规则注册表、编码生成器、字典管理 | 非标日期/数字/枚举可归一；编码可重复生成且一致性校验通过 |
| P4：校验 + 标准输出 + 核验 | 原“规则校验 + 标准模板输出 + 结果核验” | 行级校验报告、标准 xlsx、转换审计报告 | 错误数据被拦截且有行/列级原因；输出文件与目标模板逐列一致 |
| P5：批量、稳定与易用性 | 收尾 | 批量目录转换、方案复用、回归测试集、使用文档（可选的 GUI/Web） | 同格式文件复用方案转换成功；历史金标准回归全绿 |

开发约定：每个阶段结束保证代码可运行并提交 Git；每个模块完成时单独提交。

## 2. P1：第一阶段详细计划

### 2.1 阶段结论

按 PROJECT.md 编号，DeepSeek AI 接入（第一阶段）已完成。从当前仓库状态出发，接下来要开发的“第一阶段”是：

> **P1：工程骨架 + Excel 读取与结构探查，交付一个可运行的 `inspect` 工具。**

### 2.2 选择依据

1. 当前仓库只有空 `main.py` 和一个连通性验证脚本，没有包结构、数据契约、错误体系、测试体系；后续所有模块都依赖这些地基。
2. 字段映射、清洗、校验都依赖“先看懂源文件”，第一步是稳定读取并输出结构画像；该步骤必须完全确定性、可测试，不应混入 AI 的不确定性。
3. P1 结束可拿到真实文件的“结构体检报告”，是向业务方确认映射方案与收集目标模板的最佳沟通载体。

### 2.3 范围内与范围外

**范围内：**

- 建立包结构、配置加载、日志、CLI 框架、基础异常分类；
- 数据契约：转换任务、Sheet 原始数据、结构画像、校验问题等基础模型；
- Excel 读取：xlsx/csv，多 Sheet，保留原始文本与行号，避免 pandas 类型推断破坏格式；
- 结构探查：候选表头行识别、数据区边界判断、列名/样例值统计、空值/重复/混合类型等基础质量检查；
- 输出可读的源文件结构报告（控制台 + 文件）；
- 创建样例测试文件与单元测试，全流程不调用 DeepSeek。

**范围外（明确不做）：**

- 不接入 AI（现有 DeepSeek 脚本仅保留为连通性验证，后续在 P2 工程化为正式模块）；
- 不做字段映射、清洗、编码、校验、标准输出；
- 不做 GUI/Web。

### 2.4 验收标准

- 对任意混乱 Excel（含表头不在第 1 行、前面有标题行、混入说明文字、字段命名不统一）能输出结构报告；
- 报告包含：Sheet 清单、每个 Sheet 的候选表头与置信度、数据行数/列数、空值与疑似重复统计、需要人工关注的列；
- 读取阶段不丢行、不串行，输出中保留原始行号可用于追溯；
- 单测覆盖多 Sheet、标题行、合并单元格、混合类型、空文件、文件损坏等典型场景；
- `.env.example` 提供配置模板，真实 `.env` 不入库。

### 2.5 任务拆分

1. 确定包结构、配置与日志规范；
2. 定义核心数据模型和 Pipeline 阶段接口（为 P2~P4 预留扩展点）；
3. 实现 Excel 读取器（xlsx/csv、类型保真、错误分级）；
4. 实现基础结构探查器（确定性表头识别 + 质量统计）；
5. 实现 `inspect` CLI 与结构报告输出；
6. 建立 `tests/fixtures` 样例集（合成的混乱 Excel）；
7. 分模块提交 Git。

## 3. 后续阶段需要准备的输入

进入 P2 前建议准备：

- 1~2 份脱敏后的真实源 Excel（覆盖两种以上混乱格式）；
- 目标系统标准导入模板（xlsx 样例即可）；
- 少量人工转换后的正确结果，作为 P2 映射正确性的对照。

## 4. 风险与注意点

- **AI 与规则边界**：必须坚持“规则优先、AI 辅助”，防止 AI 输出直接污染主数据；
- **数据出域**：默认只向 AI 发送列名与抽样值，上传全量数据前需业务确认；
- **映射方案复用**：方案必须独立于具体文件持久化，避免每次转换重复配置；
- **审计前移**：行级溯源与转换日志从 P1 的数据契约开始设计，后期补成本高。
