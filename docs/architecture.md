# E-Master 架构设计文档

> 版本：v0.1（评审稿）
> 状态：待评审
> 关联文档：[开发阶段计划](./development-plan.md)

## 1. 背景与项目定位

E-Master 是一款基于 Python 和 AI 能力的 Excel 自动化转换工具，服务于设备主数据维护场景。

业务痛点：

1. Excel 来源复杂；
2. 字段名称不统一；
3. 数据格式不规范；
4. 编码规则复杂；
5. 人工转换效率低；
6. 容易出现遗漏和错误。

工具目标：将人工整理、格式混乱、字段不统一的 Excel 数据，通过规则处理和 AI 辅助转换，生成符合系统导入要求的标准 Excel 文件。

## 2. 项目目标分析

### 2.1 核心目标

以“规则处理 + AI 辅助”两条路径，把来源复杂的 Excel 转换为符合目标系统导入要求的标准文件，替代人工整理工作。

### 2.2 可衡量的目标

| 维度 | 目标描述 |
|---|---|
| 输入 | 能读取来源复杂、格式混乱的 Excel（多 Sheet、标题行不固定、合并单元格、说明文字混入、字段命名不统一、数据格式不规范） |
| 处理 | 规则负责确定性转换（字段映射、格式归一、校验），AI 负责模糊场景（表头识别、映射建议、非标值归一建议），AI 输出为“可确认的候选”，不直接改数据 |
| 输出 | 生成符合目标系统导入模板的标准 Excel，错误可定位、可解释 |
| 效率 | 同一类来源文件只需一次映射配置，之后可批量重复转换，无需每次重新让 AI 判断 |
| 质量 | 任何被拒绝的数据都必须有行级、字段级的校验原因，避免“悄悄丢数据” |

### 2.3 关键约束

1. **规则是主体，AI 是辅助。** 设备主数据的正确性不能完全交给 LLM；AI 适合识别、建议、解释，不是唯一正确性来源。
2. **映射方案可复用。** 设备主数据往往周期性维护（月报/周报），必须把“转换方案”与“具体文件”分离：同格式文件可直接复用已有方案。
3. **转换过程可追溯。** 每一行数据的来源 Sheet、原始行号、经过的清洗/编码规则都应可查回。
4. **数据可能敏感。** 数据上传 DeepSeek 前应有明确边界：默认只发送列名、抽样值、目标字段清单，不发送全量数据。

### 2.4 待确认事项（不阻塞架构设计）

- 目标系统的标准导入模板（Sheet、列、字段顺序、必填性、值域）；
- 设备编码规则的具体算法与字典（可先用脱敏样例）；
- 3~5 份真实来源 Excel 及人工转换的正确结果（作为金标准测试数据）；
- 数据保密要求：是否允许样例数据出网。

## 3. 总体技术架构

### 3.1 总体思路：管道式流水线 + 分层插件化

项目本质是一条“转换流水线”：同一份数据依次经过读取、分析、映射、清洗、编码、校验、输出、核验。因此采用 Pipeline（管道）架构，每个阶段是独立模块，输入输出以明确数据契约约束，可独立开发、独立测试。

```text
源 Excel/CSV
    │
    ▼
① 读取探查 ──► ② 结构分析 ──► ③ 字段映射 ──► ④ 数据清洗 ──► ⑤ 编码生成
                                                                    │
    ▲  AI 辅助（DeepSeek）：表头识别 / 映射建议 / 非标值归一建议      ▼
    │                                                         ⑥ 规则校验
    │                                                                    │
    ▼                                                                    ▼
配置层：映射方案 YAML / 编码字典 / 清洗规则 / 校验规则 / Prompt  ⑦ 标准模板输出
                                                                         │
                                                                         ▼
                                                                 ⑧ 核验与审计报告
```

### 3.2 架构原则

1. **规则优先、AI 辅助**：能确定性完成的不调 AI；AI 只处理规则无法覆盖的识别与建议。
2. **方案与数据分离**：映射方案、编码字典、校验规则是配置文件（YAML/Excel），不是代码，业务人员可维护。
3. **AI 可替换、可离线**：AI 服务封装在接口之后，测试与离线场景可用确定性实现替代；网络或 API 失败不中断主流程。
4. **全程审计**：从第一阶段起即记录行级来源与转换步骤。

### 3.3 分层设计

| 层 | 内容 |
|---|---|
| 入口层 | CLI（后续可扩展 GUI/Web API），接收文件路径、映射方案、输出目录 |
| 编排层 | 转换任务调度、阶段串联、错误处理、进度与日志 |
| 领域核心层 | 数据结构探查、字段映射、清洗规则引擎、编码规则、校验、核验；纯业务逻辑，不依赖 AI |
| AI 服务层 | DeepSeek 客户端封装、Prompt 模板、结构化响应解析（Pydantic）、降级策略 |
| 基础设施层 | Excel 读写、文件管理、日志、配置加载、测试夹具 |

### 3.4 关键技术决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 处理架构 | Pipeline 阶段式 | 每阶段独立测试，符合模块化设计原则 |
| 核心数据结构 | pandas DataFrame + 元数据上下文 | 适合表格变换；读取时统一按文本读入，避免 pandas 自动推断破坏格式 |
| 阶段间契约 | Pydantic 数据模型 | 契约清晰，AI 结构化输出可直接校验 |
| AI 输出 | 强制 JSON + Schema 校验 | 避免 AI 自由文本混入业务逻辑 |
| 映射/规则配置 | YAML + 外部字典 Excel | 与代码解耦，业务人员可维护 |
| Excel 标准模板 | 模板文件本身即规格来源 | 避免代码里写死列名，目标模板变更只需换模板 |
| 运行形态 | 先 CLI，引擎与界面分离 | 核心逻辑不依赖界面，后续加桌面/Web 不重写 |
| 审计 | 从第一版即做行级溯源 | 防止数据“悄悄出错” |
| 数据安全 | 默认只传抽样数据，提供脱敏开关 | 设备数据可能敏感 |

### 3.5 代码结构建议

```text
e_master/
├── main.py                  # CLI 入口
├── config/                  # 环境变量加载、全局配置
├── core/                    # 领域核心（不含 AI 调用）
│   ├── models/              # 数据契约：任务、Sheet、映射、校验问题
│   ├── pipeline/            # 编排器、阶段基类、上下文
│   ├── loader/              # Excel 读取
│   ├── analyzer/            # 结构分析、表头识别
│   ├── mapper/              # 字段映射
│   ├── cleaner/             # 清洗规则执行器
│   ├── codegen/             # 编码规则引擎
│   ├── validator/           # 校验规则引擎
│   ├── exporter/            # 标准模板输出
│   └── auditor/             # 结果核验与审计
├── ai/                      # DeepSeek 客户端、Prompt、响应解析
├── rules/                   # 内置规则注册表
├── profiles/                # 映射方案、字典、校验规则（配置数据）
├── tests/
│   └── fixtures/            # 样例 Excel 与金标准结果
└── .env.example             # 环境变量模板（不含真实 Key）
```

## 4. 核心模块划分

| 模块 | 职责 | 关键输入 → 输出 |
|---|---|---|
| 配置模块 | 加载 `.env`、路径、运行参数；保证 API Key 不进代码 | 环境变量 → 全局配置 |
| Excel 读取模块 | 读取 xlsx/csv，处理多 Sheet、编码、类型保真 | 源文件 → 每 Sheet 原始数据 + 原始行号 |
| 结构分析模块 | 探测有效 Sheet、表头行位置、字段候选、数据区边界、基础质量统计 | 原始数据 → Sheet 结构画像 |
| AI 服务模块 | DeepSeek 封装：结构识别、映射建议、非标值归一建议；结构化输出 | 列名/抽样值/目标字段 → 带置信度的候选建议 |
| 字段映射模块 | 应用映射方案，支持别名、组合、默认值、AI 候选确认 | 源画像 + 映射方案 → 标准字段数据 |
| 数据清洗模块 | 去空格、全半角、日期/数字/枚举归一、空值处理、去重 | 标准字段数据 + 清洗规则 → 干净数据 |
| 编码规则模块 | 按规则/字典生成编码；规则外的编码模式借助 AI 建议 | 干净数据 + 编码字典 → 编码结果 |
| 规则校验模块 | 必填、长度、唯一性、值域、字段间逻辑校验 | 转换后数据 + 校验规则 → 行级校验报告 |
| 标准输出模块 | 按标准模板写出 xlsx，列顺序、类型、Sheet 与模板一致 | 通过校验的数据 + 模板 → 标准 Excel |
| 结果核验模块 | 汇总转换统计、错误分布、抽样核验、生成转换报告 | 全过程审计记录 → 核验报告/审计日志 |
| 编排与入口 | 串联各阶段、异常分类处理、断点/进度、CLI 命令 | 用户指令 → 最终输出目录 |

横切能力：日志分级、错误分类（文件错误/规则错误/AI 错误/数据错误）、测试夹具与金标准比对。
